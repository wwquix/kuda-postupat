# Honest admission recommendations v1

`M-RECOMMENDATIONS-01` добавляет публичный read-only подбор на
`/recommendations` и typed endpoint `GET /api/recommendations`. Первая версия
сопоставляет пользователя только с уже сохранёнными полями каталога. Она не
строит вероятность поступления и не дополняет отсутствующие данные догадками.

## Поддерживаемые входные данные

API принимает:

- `score` — целое число от 0 до 500 включительно;
- `city`, `region`;
- `ownership_type`, `institution_kind`;
- `category`;
- `study_form`, `funding_type`;
- `online_monitoring` — наличие реализованного платформой online-adapter;
- `page` от 1 и `page_size` от 1 до 100, по умолчанию 20.

Значения селектов frontend получает из `GET /api/catalog/meta`. Фильтры
применяются в backend repository; React не отбрасывает и не ранжирует результаты.
Endpoint публичный и не требует token анонимного профиля. GET не создаёт профиль,
не пишет в SQLite и не выполняет live scraping.

## Три класса результата

Каждая карточка содержит один явный `result_class`, человекочитаемый
`result_label`, конкретные `match_reasons` и пояснения о покрытии.

### `MONITORED_STATUS`

Разрешён только для импортированной Program, которую уже поддерживает текущий
monitoring domain, при заданном балле и достаточно свежем snapshot. Статус,
место и диапазон порога вычисляет существующий `program_monitoring_for_score`,
который использует общие `offering_latest` и `calculate_metrics`. Recommendation
service не дублирует расчёт и не переименовывает его результат.

### `PARAMETER_MATCH`

Program или University соответствует выбранным полям каталога, но статус
поступления вычислить нельзя. Карточка показывает обе фразы:

- «Совпадает с выбранными параметрами»;
- «Недостаточно данных для оценки поступления».

Такое совпадение не является подтверждением или гарантией поступления.

### `INSUFFICIENT_COVERAGE`

Нужное покрытие ещё не импортировано: например, у Program отсутствуют
импортированные Offering или у University отсутствуют импортированные Program.
Пояснение говорит о границе платформы и не трактует отсутствие строки как
отсутствие реальной программы или варианта обучения в вузе.

## Детерминированный порядок

Никаких весов, скрытого match score или ML нет. Порядок фиксирован:

1. `MONITORED_STATUS`, затем `PARAMETER_MATCH`, затем `INSUFFICIENT_COVERAGE`;
2. больше совпавших явно выбранных catalog-параметров;
3. больше импортированного покрытия: число Offering для Program, затем число
   Program и Offering для University;
4. нормализованное стабильное имя University/Program и database ID как
   окончательный tie-breaker.

`score` участвует в существующем monitoring calculation, но не считается
catalog-совпадением. Сервер сначала фильтрует и ранжирует полный набор, затем
независимо формирует страницы коллекций `programs` и `universities` с общими
`page` и `page_size`.

## Профиль и URL

Существующий personal score может предварительно заполнить пустую начальную
форму. Открытие страницы не создаёт профиль. Редактирование и применение формы
записывает score только в URL и не меняет профиль. Кнопка «Сохранить балл в
профиле» — отдельное явное действие; только оно может лениво создать профиль.
Значение `0` сохраняется как введённый балл, а не превращается в отсутствие.

URL страницы поддерживает `score`, все перечисленные фильтры, `page` и служебный
`applied=true`, который отличает начальную форму от явно запущенного подбора без
фильтров. Значения по умолчанию опускаются; невалидные enum/meta-значения и page
без положительного целого безопасно удаляются или возвращаются к page 1.
Refresh и Back/Forward восстанавливают форму и результаты. Новый запрос отменяет
устаревший через `AbortController`; ошибка API показывается отдельно от пустого
результата.

## Ограничения

- Реальное мониторинговое покрытие сейчас есть только у поддержанной BSEU
  Offering и зависит от freshness сохранённых данных.
- University никогда не получает общий «статус поступления»: текущий расчёт
  относится к конкретной Program/Offering.
- Отсутствующие места, стоимость, дедлайны, проходные баллы и варианты обучения
  не подставляются и не интерпретируются.
- Subject matching отложен: сохранённого нормализованного и достаточно полного
  контракта совместимости предметов пока нет.
- Дополнительные импорты, сравнение, ML/вероятности и accounts/cross-device
  profile не входят в эту версию.
