# Аудит источника программ БГЭУ

Проверка выполнена 16 июля 2026 года без записи в SQLite. Официальный XML
`https://bseu.by/abiturient/xml/1.xml` ответил HTTP 200; проверенный снимок
имел `genTime="16.07.2026 18:00"` во всех 77 строках. Машиночитаемый результат
зафиксирован в `docs/data/bseu-program-import-candidates.json` и проверяется
схемой `docs/data/bseu-program-import-candidates.schema.json`.

## Что представляет строка

`DATAPACKET / ROWDATA / ROW` — это срез текущей конкурсной ситуации для
одной комбинации:

`spid + frmid + IDFINANCE`.

- `spid`, `spname` задают внутренний идентификатор и название специальности в
  конкурсном источнике;
- `fakid`, `fkname` задают подразделение, указанное именно для этого среза;
- `frmid`, `frname` задают форму обучения;
- `IDFINANCE=18` означает бюджет, `IDFINANCE=19` — платную основу;
- для бюджетной строки план берётся только из `PlanBudj`, для платной — только
  из `PlanVneBudj`;
- `AllCount`, `G_*` и `genTime` относятся к текущему мониторингу, а не к
  постоянной карточке программы.

В проверенном снимке все 77 ключей уникальны. Это не 77 программ: строки
повторяют одну специальность для разных форм и основ финансирования. Получено
23 уникальных `spid` и 20 названий после удаления краевых пробелов.

| Измерение | Строк |
|---|---:|
| Дневная (`frmid=1`) | 39 |
| Заочная (`frmid=2`) | 12 |
| Заочная сокращённая, 3 года (`frmid=5`) | 20 |
| Заочная дистанционная (`frmid=6`) | 3 |
| Заочная сокращённая на базе высшего образования (`frmid=7`) | 3 |
| Бюджет (`IDFINANCE=18`) | 33 |
| Платная (`IDFINANCE=19`) | 44 |

Дневные, заочные, сокращённые и дистанционные варианты различаются надёжно
по `frmid`; бюджетные и платные — по `IDFINANCE`. Одинаковые `PlanBudj` и
`PlanVneBudj`, присутствующие в паре строк, не превращают строки в дубликаты:
основа финансирования выбирает применимый план.

## Явные и отсутствующие семантики

| Поле | Вывод |
|---|---|
| Название программы | Явно в `spname`; нормализуются только пробелы. |
| Внутренний ключ источника | Явно в `spid`, но его межгодовая стабильность официально не документирована. |
| Официальный код специальности | В XML отсутствует. Для «Экономической информатики» код `6-05-0311-05` подтверждён отдельным официальным планом БГЭУ; для остальных оставлен `null`. |
| Специализация/профиль | Отсутствует; везде `null`. |
| Факультет | `fkname` явен для строки, но иногда содержит несколько факультетов или меняется между формами одного `spid`; такое значение нельзя автоматически объявлять единственным факультетом Program. |
| Форма обучения | Явна в `frmid`/`frname`. Канонические `full_time`, `part_time`, `distance` однозначны; формы 5 и 7 честно отображаются в существующий enum как `other`, при этом исходные id и подписи сохранены в аудите. |
| Основа финансирования | Явна: 18 — `budget`, 19 — `paid`; это уже подтверждено действующим парсером и мониторингом. |
| Год приёма | В самом XML поля года нет. Значение 2026 опирается на отдельный официальный план приёма БГЭУ и зафиксированное решение `docs/admission-year-evidence.md`, а не выводится из системной даты. |
| План приёма | Явен после выбора `PlanBudj` или `PlanVneBudj` по `IDFINANCE`; во всех 77 строках выбранный план положителен. |

Источник содержит только активную таблицу поданных документов. Наличие 20
названий не доказывает полноту каталога программ БГЭУ, не описывает профили и
не заменяет официальный каталог специальностей.

## Program и ProgramOffering

В `Program` допустимо переносить только устойчивые факты: БГЭУ, название,
подтверждённый код (если он есть) и факультет только при отсутствии конфликта.
`spid` остаётся ключом строки источника и доказательством дедупликации, но не
выдаётся за официальный код специальности.

В `ProgramOffering` относятся год приёма, каноническая форма, основа
финансирования и применимый план. Предлагаемый ключ соответствует действующей
модели:

`Program + admission_year + study_form + funding_type`.

Исходные `spid`, `frmid` и `IDFINANCE` остаются в candidate key, чтобы импорт
мог остановиться при изменении структуры или неожиданной коллизии.

### «Экономическая информатика»

Обе строки имеют `spid=6`, `frmid=1` и факультет «Цифровой экономики»:

| Финансирование | Source key | План | Каноническое соответствие |
|---|---|---:|---|
| Бюджет | `spid=6 / frmid=1 / IDFINANCE=18` | 25 | тот же Program, новое `2026 + full_time + budget` Offering |
| Платная | `spid=6 / frmid=1 / IDFINANCE=19` | 60 | существующие Program `6-05-0311-05` и `2026 + full_time + paid` Offering |

Это подтверждает разделение Program и Offering: пара строк не должна создавать
два Program.

## Коллизии, требующие проверки

Три нормализованных названия встречаются под разными `spid`:

| Название | `spid` | Строк |
|---|---|---:|
| Бухгалтерский учет, анализ и аудит | 17, 140 | 7 |
| Правоведение | 101, 143 | 6 |
| Экономика и управление | 139, 142 | 7 |

Источник показывает разные подразделения и варианты обучения, но не сообщает
официальные коды или профили, позволяющие доказать, являются ли пары одним
Program, разными Program или отдельными треками. Эти 20 строк имеют
`needs_review`; предлагаемые Program и ProgramOffering match keys для них
намеренно равны `null`. Их нельзя автоматически сливать по названию или
разделять по `spid`.

Отдельно `spid=140` имеет разные значения `fkname` для дневной и заочной форм.
До официальной проверки факультет нельзя закреплять на Program как единичный
факт.

## Итог и блокеры

Статусы относятся только к 77 строкам проверенного XML, а не к неизвестным
программам вне активной конкурсной таблицы:

| Статус кандидата Offering | Количество |
|---|---:|
| `confirmed` | 57 |
| `needs_review` | 20 |
| `unavailable` | 0 |

57 подтверждённых строк образуют 17 однозначных Program identities. Ещё шесть
`spid` входят в три коллизии названий. `unavailable=0` означает лишь, что ни
одна из наблюдаемых строк не была отброшена как неразбираемая; количество
отсутствующих в XML реальных программ БГЭУ неизвестно и не подсчитывается.

Точные блокеры полного импорта:

1. XML не публикует официальные коды для 22 из 23 `spid`.
2. XML не публикует специализации/профили.
3. Три названия имеют неоднозначное соответствие шести `spid`.
4. Факультет иногда агрегирован или зависит от формы.
5. Год кампании подтверждается внешним официальным планом, а не полем XML.
6. Источник не подтверждает полный каталог БГЭУ и не гарантирует стабильность
   внутренних id между кампаниями.

## Рекомендация для M-BSEU-PROGRAM-IMPORT-01

Следующий milestone допустим, потому что подтверждённые кандидаты есть. Его
точная граница: импортировать только 57 `confirmed` Offering-кандидатов,
относящихся к 17 однозначным Program identities; переиспользовать существующие
Program «Экономическая информатика» и paid Offering, поэтому создать не более
16 новых Program и 56 отсутствующих Offering. Все значения брать из
машиночитаемого аудита, импорт сделать идемпотентным и fail-closed.

Не импортировать 20 `needs_review` строк, не заполнять отсутствующие коды и
профили, не объявлять этот набор полным каталогом. Формы 5 и 7 хранить как
каноническое `other` только с сохранённой связью с исходным candidate key;
неожиданная коллизия canonical Offering key должна останавливать импорт.
Новые Offering не считать автоматически подключёнными к scheduler/Telegram:
расширение мониторинга не входит в этот import milestone.

## Безопасный запуск импорта

Команда всегда требует явный путь к уже мигрированной SQLite. Без `--apply`
она выполняет read-only, WAL-aware dry-run по текущему committed-состоянию и не изменяет базу:

```powershell
Set-Location backend
..\.venv\Scripts\python.exe -m app.cli import-bseu-programs --database 'D:\backups\admission-copy.db'
```

Перед применением к production-копии нужно остановить сервис и сделать
проверенную отдельную резервную копию SQLite вместе с актуальным WAL, если он
существует. Запись включается только явным флагом:

```powershell
..\.venv\Scripts\python.exe -m app.cli import-bseu-programs --database 'D:\backups\admission-copy.db' --apply
```

Для production-style базы первый apply должен сообщить `confirmed_candidates=57`,
`needs_review_skipped=20`, `program_identities_expected=17`,
`programs_created=16`, `programs_reused=1`, `offerings_created=56`,
`offerings_reused=1`, `conflicts=0`, `writes_applied=true`. Повторный apply
должен показать 0 созданных, 17 переиспользованных Program и 57
переиспользованных Offering.

После apply проверяются целостность и точные итоговые количества:

```powershell
@'
import sqlite3
import sys

with sqlite3.connect(sys.argv[1]) as connection:
    print("integrity:", connection.execute("PRAGMA integrity_check").fetchone()[0])
    print("foreign keys:", connection.execute("PRAGMA foreign_key_check").fetchall())
    print("BSEU programs:", connection.execute(
        "SELECT COUNT(*) FROM programs p JOIN universities u ON u.id=p.university_id WHERE u.code='bseu'"
    ).fetchone()[0])
    print("BSEU offerings:", connection.execute(
        "SELECT COUNT(*) FROM program_offerings o JOIN programs p ON p.id=o.program_id "
        "JOIN universities u ON u.id=p.university_id WHERE u.code='bseu'"
    ).fetchone()[0])
'@ | ..\.venv\Scripts\python.exe - 'D:\backups\admission-copy.db'
```

Ожидается `integrity: ok`, пустой `foreign keys: []`, 17 BSEU Program и 57
BSEU ProgramOffering. Импортер не удаляет строки, не создаёт monitoring/source
регистрации и откатывает всю транзакцию при любой коллизии.
